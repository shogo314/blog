Suffix Automaton について、参考になる記事や資料をまとめました。

Suffix Automaton は、文字列 $S$ のすべての部分文字列を受理する最小の DFA(決定性有限オートマトン)です(終端状態を $S$ の suffix に限ると、suffix だけを受理する最小の DFA になります)。各状態は、$S$ の中での出現位置の終端の集合(endpos)が等しい部分文字列の集まりを表します。$|S| = N \ge 2$ のとき状態数は $2N - 1$ 以下、$N \ge 3$ のとき遷移数は $3N - 4$ 以下で、1 文字ずつ末尾に追加するオンラインのアルゴリズムで線形時間で構築できます。各状態から「その状態に入らない最長の suffix」の状態へ張る suffix link は木になり、この木は逆文字列 $\mathrm{rev}(S)$ の suffix tree と同じ形です。

遷移を長さ $\sigma$(文字の種類数)の配列で持つと速いですが、メモリは $O(N\sigma)$ です。英小文字で $N = 5 \times 10^5$ なら、状態が最大 $10^6$ 個なので、`int` の配列で 100 MB ほどになります。`map` などで持つとメモリは $O(N)$ ですが、構築が $O(N \log \sigma)$ になり、定数倍も重くなります。定番の使い方には、異なる部分文字列の個数($\mathrm{len}(\mathrm{link}(v))$ を suffix link の先の状態の最長の長さとして、初期状態以外の各状態 $v$ について $\mathrm{len}(v) - \mathrm{len}(\mathrm{link}(v))$ を足す。答えは 64 bit 整数が必要)、ある文字列の出現回数(suffix link の木の部分木で endpos の大きさを数える)、2 つの文字列の最長共通部分文字列(片方の Suffix Automaton の上でもう片方を読み、遷移できないときは suffix link をたどる)などがあります。

## まず読むもの

- [Suffix Automaton](https://yosupo.hatenablog.com/entry/2021/01/31/160215)(よすぽの日記)

  - 「性質」と「問題例」の節で「部分列」と書いているところは「部分文字列」の意味です。また、実装は `last` を戻して複数の文字列を追加する使い方には対応していません(下の「複数の文字列」の節を参照)。
- [Suffix Automaton](https://cp-algorithms.com/string/suffix-automaton.html)(cp-algorithms、英語)
  - endpos と suffix link の定義から、構築アルゴリズム、その正当性と計算量、状態数 $2n - 1$・遷移数 $3n - 4$ の証明までを順に説明しています。後半の応用の節は、異なる部分文字列の個数、辞書順 $k$ 番目の部分文字列、出現回数、最初の出現位置、2 つや複数の文字列の最長共通部分文字列など 11 個あります。e-maxx.ru のロシア語の記事の翻訳です。
  - コードは C++ で、遷移を `map<char, int>` で持ち、状態をグローバルな配列に入れる書き方です。遷移を配列で持つ場合のメモリと速度の違いにも触れています。

## 構築

構築は、末尾に文字 $c$ を追加するたびに、直前の文字列全体の状態から suffix link をたどって $c$ の遷移を張り、必要なら状態を分割(clone)する、という手順です。

- [Suffix Automatonでもやもやした部分をなんか書いただけ](https://pazzle1230.hatenablog.com/entry/2020/04/10/030325)(迷いませんか？)
  - cp-algorithms の構築の手順について、「なぜ suffix link をさかのぼりながら遷移を張ってよいのか」「なぜ clone が必要なのか」などの疑問に答える形で補足しています。$S = \texttt{abcbcc}$ に 1 文字ずつ追加していく図があります。
  - 筆者自身が「多分」と書いている箇所もあり、cp-algorithms と合わせて読む補足として使うのがよいです。
- [A short guide to suffix automata](https://codeforces.com/blog/entry/20861)(quasisphere、Codeforces、英語)
  - 「部分文字列を 1 文字ずつ聞かされて、出現しうる位置の集合だけを覚えておく」というゲームから状態の意味を導き、suffix link、構築、C++ の実装、簡単な応用を短く説明しています。suffix link の木が逆文字列の suffix tree になることにも触れています。
  - 「異なる部分文字列の個数は経路の個数」とあるのは、空の経路を含むので、実際の個数は $1$ を引いたものです。

## 複数の文字列

複数の文字列のすべての部分文字列を受理するオートマトン(一般化 Suffix Automaton)は、1 つの Suffix Automaton に「`last` を初期状態に戻してから次の文字列を追加する」ことを繰り返して作ることもあります。ただし、そのままだと追加したい文字の遷移がすでにある場合に無駄な状態ができるので、その場合を別に扱う必要があります。

- [广义后缀自动机](https://oi-wiki.org/string/general-sam/)(OI Wiki、中国語)
  - 複数の文字列から Trie を作り、BFS の順に Suffix Automaton の構築を行う方法を説明しています。区切り文字で連結する方法や `last` を戻す方法(「伪广义后缀自动机」)の問題点、すべての文字列の異なる部分文字列の個数や複数の文字列の最長共通部分文字列への応用も扱っています。C++ のコードは遷移を配列で持っています。
- 下の USACO Guide の例題「Standing Out from the Herd」の解答コードは、`last` を戻して追加する方法で、すでに遷移がある場合も正しく扱っています。

## Suffix Tree・Suffix Array との関係

suffix link の木は $\mathrm{rev}(S)$ の suffix tree なので、$\mathrm{rev}(S)$ の Suffix Automaton を作れば $S$ の suffix tree が得られ、さらにその DFS 順から $S$ の Suffix Array が得られます。Suffix Array と LCP 配列で解ける問題の多くは Suffix Automaton でも解けるので、どちらで解くかは好みや問題によります。

- [String Suffix Structures](https://usaco.guide/adv/string-suffix)(USACO Guide、英語)
  - Suffix Automaton、Suffix Tree、Suffix Array を相互に変換する方法(suffix tree の DFS から Suffix Array を作る、Suffix Array と LCP 配列から suffix tree を作る、Suffix Automaton の suffix link から suffix tree を作る)を C++ のコード断片で紹介し、例題を一般化 Suffix Automaton で解いています。どの構造でも解ける問題の一覧があります。解説は短く、詳しくは cp-algorithms などへのリンクに任せています。
  - suffix tree を扱う 2 つのコード断片は、ループ変数がグローバルな配列と同じ名前(`c` や `l`)になっていて、そのままではコンパイルできません。

## AtCoder Algorithm Lectures

Suffix Automaton を扱う講座はまだありません。文字列の分類にある講座は、今のところ「文字列の並べ替えと辞書順最小化」だけです。

## 実装

- [string/suffix_automaton.hpp](https://maspypy.github.io/library/string/suffix_automaton.hpp)(maspy's library)
  - C++ の実装で、遷移を長さ `sigma`(既定は 26)の配列で持ちます。構築後に状態を $\mathrm{len}$ の昇順(トポロジカル順)に並べ替え、各状態の出現回数と出現位置の最小・最大も求めます。suffix link の木を作る関数、$S$ の区間 $[L, R)$ に対応する状態を求める関数、もう 1 つの文字列を読みながら最長一致を追う `next` もあります。ドキュメントはなく、説明はコード中のコメントだけです。

## 練習問題

- [Library Checker - Number of Substrings](https://judge.yosupo.jp/problem/number_of_substrings):異なる部分文字列の個数を求めます。$N \le 5 \times 10^5$ で、ライブラリの verify 用です。
- [CSES - Distinct Substrings](https://cses.fi/problemset/task/2105):上と同じく異なる部分文字列の個数を求めます。$n \le 10^5$ です。
- [CSES - Substring Distribution](https://cses.fi/problemset/task/2110):長さごとに異なる部分文字列の個数を求めます。各状態が受け持つ長さの区間に、いもす法で $1$ を足します。
- [CSES - Counting Patterns](https://cses.fi/problemset/task/2103):各パターンの出現回数を求めます。suffix link の木で各状態の endpos の大きさを数えておきます。
- [SPOJ - LCS(Longest Common Substring)](https://www.spoj.com/problems/LCS/):長さ $250000$ 以下の 2 つの文字列の最長共通部分文字列の長さを求めます。
- [SPOJ - SUBLEX(Lexicographical Substring Search)](https://www.spoj.com/problems/SUBLEX/):異なる部分文字列のうち辞書順で $K$ 番目のものを答えるクエリに答えます。各状態から出る経路の個数を数えておきます。
- [ABC433 G - Substring Game](https://atcoder.jp/contests/abc433/tasks/abc433_g):Suffix Automaton の上でコマを動かすゲームに言い換え、後退解析で勝敗を求めます([公式解説](https://atcoder.jp/contests/abc433/editorial/14604))。
- [Codeforces 235C - Cyclical Quest](https://codeforces.com/problemset/problem/235/C):$x_i$ の巡回シフトのどれかと一致する $s$ の部分文字列の個数を求めます。$x_i x_i$ を $s$ の Suffix Automaton の上で読み、同じ状態を重複して数えないようにします。
